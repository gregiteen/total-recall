# Sovereign OS Release Readiness Development Plan

- **Plane**: Projects
- **Status**: In progress
- **Created**: 2026-05-18

This plan sequences the consolidated release-readiness epic. Phases are
ordered so that low-risk correctness fixes land first and the Testing phase
runs last against a settled system. Every step maps to a checkbox in
`SOVEREIGN_OS_RELEASE_READINESS_PROJECT_TRACKER.md`.

## Phase 1 — Deployment Correctness & Quick Wins

Small, deterministic, in-scope fixes from the verification audit.

- Remove the dead `finetune` route from `bin/total-recall.mjs` (the
  `COMMANDS` map and `printHelp()`), and reconcile the stale JSDoc command
  list, which references `export`/`import`/`reindex` that were never
  registered.
- Correct `README.md`: drop the `finetune` CLI row and the line 61 QLoRA
  mention; fix the false "compile/backup/sync/reindex have been removed"

Exit: `node bin/total-recall.mjs --help` lists only registered commands;
README matches the CLI; every `connect` client has a guide.

## Phase 2 — macOS Deployment Parity

Bring macOS to systemd parity so `deploy` is genuinely one-click on Darwin.

- Add a launchd plist template under `templates/` for the server and the
  daemon (parallel to the existing `.service` units).
- In `deploy.mjs`, branch on platform: install + `launchctl load` the plist
  on macOS where the systemd path runs on Linux.
- In `daemon.mjs`, delegate `start`/`stop`/`status` to `launchctl` on macOS
  the way it delegates to `systemctl` on Linux.
- Support the DuckDNS IP-update job on macOS via a launchd interval job
  instead of cron.

Exit: a macOS clean-host deploy yields an auto-starting, auto-restarting
daemon with no manual plist authoring.

# OB1-Inspired Enhancements

Phases 7–9 add six storage-agnostic ideas drawn from the OB1 (Open Brain)
comparison. They are sequenced **after** release readiness so the system is
verified-stable before new surface area is added. Every enhancement must
stay file-native — no database, no vector store (see PRD Non-Goals). New UI
must be gated behind a `.agent/memory-vault/preferences/` feature flag until
verified, per the project-management feature-flag protocol.

## Phase 7 — Memory Intelligence Upgrades

- Add SHA-256 content fingerprinting at ingest so identical content arriving
  from multiple IDE session sources produces one node, not duplicates.
  Extends `session-watcher.mjs` and feeds the Dream Cycle Memory Synthesizer.
- Add local semantic search: generate embeddings with a local Ollama
  embedding model, persist vectors in a derived index file (regenerated by
  `compile`), and add a semantic recall path alongside the existing tf-idf
  route.

Exit: duplicate ingestion is provably collapsed; a semantic query surfaces a
node tf-idf misses; no DB dependency introduced.

## Phase 8 — Capture And Surface Expansion

- Add Slack/Discord quick-capture: an inbound bot that classifies and writes
  messages as SSSS nodes, parallel to the existing Telegram path.
- Add dashboard views: an SSSS node-connections graph, reasoning traces, and
  a duplicates/conflict resolution UI that surfaces the existing
  conflict-detector output and merge proposals.

Exit: a chat message becomes a valid node; the dashboard renders the graph
and resolves a conflict end to end; new UI is feature-flagged.

## Phase 9 — Community And Repo Tooling

- Add a community submission pipeline: issue templates for skill/recipe
  submissions, a `metadata.schema.json`, and a CI gate that validates them.
- Add Claude-in-CI workflows: issue-triage and PR-review GitHub Actions for
  the total-recall repo.

Exit: a sample submission passes the gate; the workflows run on a test
issue/PR.

## Phase 10 — Enhancement Acceptance And Regression

The mandatory closing testing phase for the enhancement work.

- Full `vitest` suite green after Phases 7–9.
- `/code-quality` reports 0 TS and 0 lint.
- Clean-Account VFS Initialization re-run still passes with enhancements on.
- Sovereign-thesis audit: confirm no database or vector-store dependency was
  introduced — embeddings and indexes remain plain files.

Exit: the full epic is eligible to move to `completed/`.
