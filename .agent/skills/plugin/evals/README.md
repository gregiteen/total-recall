# Evals

Proof that the recipe and its checks work.

Each case is a synthetic plugin whose correct outcome is already known. Five are **real defects observed in this ecosystem**; one is a plugin that follows the recipe and must be **accepted**. A checker that only ever rejects, or only ever accepts, proves nothing.

```
node evals/run.mjs                 # every case
node evals/run.mjs --case <name>
node evals/run.mjs --json
node evals/run.mjs --keep          # keep the temp fixture for inspection
```

Exit code is non-zero unless every case behaves as expected.

## How a case is judged

A case declares the failures it expects. It passes when `scripts/record.mjs` reports **exactly** those and nothing else:

- A defect case passes only if the checker **catches** it. A checker that looks at nothing fails here.
- The correct-plugin case passes only if there are **no** failures. An over-eager checker fails here.
- A case whose expectation is empty treats any failure as unexpected.

## The cases

| Case | Defect it encodes | Expected |
| --- | --- | --- |
| [`fabricated-seed`](cases/01-fabricated-seed.mjs) | a card seeding a telemetry reading — a literal hostname, uptime, load average and `usedPercent: 99.1` before any command ran, commented "Retain fallback telemetry" | `no seeded values` |
| [`reassuring-default`](cases/02-reassuring-default.mjs) | a card reading three fields its command never returns and defaulting to "Up to date", so a repository with three unpushed commits rendered clean | `no reassuring default` |
| [`declared-template`](cases/03-declared-template.mjs) | a manifest declaring `card_layout` with a template name and region list — the vocabulary that made 24 of 34 plugins identical | `no template` |
| [`card-collects-credential`](cases/04-card-collects-credential.mjs) | a card collecting an API key in a password field and dispatching the raw value — generated by the old scaffolder | `never collects a credential`, `never transmits a credential` |
| [`host-leak-in-scaffold`](cases/05-host-leak-in-scaffold.mjs) | a capability calling the `total-recall` binary for credentials and shipping `https://example.com/checkout/success` | `no Total Recall dependency`, `no placeholder values` |
| [`correct-plugin`](cases/06-correct-plugin.mjs) | a plugin that follows the recipe: one bespoke face, real data only, credentials resolved through auth in the CLI, and a host-free capability | no failures |

## Adding a case

A case is a module exporting `{ name, why, files, expect }`:

```js
export default {
  name: 'kebab-case-name',
  why: 'the failure mode this encodes, and what it costs',
  files: { 'plugin.json': '…', 'cli.mjs': '…', 'ui/card.js': '…' },
  expect: { fail: ['the check name record.mjs must report'] },
}
```

Rules:

- `why` states the **cost** of the defect, not just its shape.
- `expect.fail` lists check names as `record.mjs` prints them. Empty means "must be accepted".
- Prefer a case grounded in something that actually happened. An invented defect tests the checker against your imagination; a real one tests it against the ecosystem.
- If a new case cannot be made to fail, the check behind it is decorative — fix the check, not the case.
